# 需求文档

## 1. 应用概述

### 1.1 应用名称
对话框网站

### 1.2 应用描述
一个仅包含对话框功能的极简网站,用户可以在对话框中输入内容并查看对话记录,所有新生成的文字内容强制转换为 Markdown 格式撰写并渲染展示。网站支持部署到 GitHub Pages,可通过 GitHub 域名访问。

## 2. 页面结构与功能说明

### 2.1 页面结构
```
对话框网站
└── 对话页面
```

### 2.2 对话页面

#### 2.2.1 页面布局
- 对话记录展示区域:显示历史对话内容
- 输入框:用户输入对话内容
- 发送按钮:提交对话内容

#### 2.2.2 功能说明
- 用户在输入框中输入文字内容
- 点击发送按钮后,输入内容显示在对话记录区域
- 对话记录按时间顺序从上到下排列,最新消息显示在底部
- 发送后输入框自动清空
- 对话记录支持滚动查看
- 所有新生成的对话内容强制按 Markdown 格式进行渲染展示,包括标题、列表、代码块、链接、加粗、斜体等常见语法

## 3. 业务规则与逻辑

### 3.1 消息发送规则
- 输入框为空时,发送按钮不可点击
- 按下回车键等同于点击发送按钮
- 每条消息自动记录发送时间

### 3.2 数据存储规则
- 对话记录需持久化存储
- 用户再次访问时可查看历史对话记录
- 数据存储使用浏览器本地存储机制

### 3.3 Markdown 强制渲染规则
- 对话记录区域中的所有新生成消息内容强制解析为 Markdown 格式
- 支持的 Markdown 语法包括:标题、列表、代码块、链接、加粗、斜体、引用等
- 原始输入内容保持不变,在展示时强制进行 Markdown 渲染
- 即使用户输入的是普通文本,也按 Markdown 规则进行解析和渲染

### 3.4 部署规则
- 网站文件支持上传到 GitHub 仓库
- 支持通过 GitHub Pages 服务进行部署
- 可通过 GitHub 提供的域名访问网站

## 4. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 输入框为空 | 发送按钮置灰,不可点击 |
| 输入内容过长 | 输入框支持多行显示 |
| 无历史记录 | 对话记录区域显示为空 |
| 输入非 Markdown 格式文本 | 强制按 Markdown 规则解析,普通文本按段落格式显示 |
| Markdown 语法不完整 | 按 Markdown 解析器的容错机制处理,确保内容可正常显示 |

## 5. 验收标准

1. 用户可以在输入框中输入文字内容
2. 点击发送按钮后,内容正确显示在对话记录区域
3. 对话记录按时间顺序正确排列
4. 发送后输入框自动清空
5. 刷新页面后历史对话记录仍然存在
6. 输入框为空时发送按钮不可点击
7. 按回车键可成功发送消息
8. 所有新生成的对话内容强制按 Markdown 格式渲染展示
9. 输入普通文本时,强制按 Markdown 规则解析并渲染
10. Markdown 渲染支持标题、列表、代码块、链接、加粗、斜体等常见语法
11. 即使输入内容不包含 Markdown 语法标记,也按 Markdown 格式进行渲染处理
12. 网站文件可成功上传到 GitHub 仓库
13. 网站可通过 GitHub Pages 部署并正常访问
14. 通过 GitHub 域名可正常访问网站的所有功能
